02部署步骤

子路径部署（挂现有官网 /cs/）是推荐形态。

  1. 解压源码模板 —— unzip skill/assets/smart-cs-src.zip，得到 111 个文件的项目目录。
  2. 装依赖 —— npm install，只有 5 个纯 JS 依赖。
  3. 生成配置 —— configure.py 写入企业档案、挂件文案与 LLM 密钥。
  4. 停机 seed —— 先停服务再 node server/seed.js，这是唯一安全顺序。
  5. 构建前端 —— 按部署路径设置 VITE_BASE，前缀错了就是白屏。
  6. 反代与守护 —— make_nginx_conf.py 出片段，pm2 start 守护进程。
  7. 验收 —— health / 登录 / 鉴权 / 公开问答 / 后台渲染，五项全绿才算交付。

03四个真实的坑

都是这次装完跑起来才发现的，不是从文档里抄的。

① 前端资源前缀不匹配 → 白屏

自带 dist 引用 /cs/assets/…。直连 Node 根路径时该路径落到 SPA 兜底，返回 text/html， 浏览器报 MIME type of "text/html"。解法：按 /cs/ 反代，或 build_frontend.sh <dir> / 重构建。

② seed 必须在服务停止时执行

sql.js 是内存库，服务运行期每次写操作都会 flush 回文件。服务在跑时 seed，种子数据会被下一次写操作 覆盖——表现为「seed 成功但登录一直失败、用户表为空」。

③ Windows Git Bash 会吃掉 /cs/

MSYS 把 --base-path /cs/ 转成 D:/…/PortableGit/cs/，生成的 Nginx 配置直接作废。 解法：MSYS_NO_PATHCONV=1，脚本路径改用 Windows 形式。

④ GitHub Pages 跑不了这个后端

Fastify 需要常驻 Node 进程和可写数据库。Pages 是纯静态托管，只能放本页这类文档。 要让所有人访问可交互客服，必须换能跑 Node 的宿主。
